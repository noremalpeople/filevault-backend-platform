# 性能记录

2026-11-19 在 Windows 11（系统构建 26300，14 个可用逻辑处理器）上实测。运行 Java 21、Spring Boot 4.1.2、原生 MySQL 8.4.13 和 Node.js 24.19.0。客户端与服务都使用本机回环地址，后端 JVM 参数为 `-Xms64m -Xmx256m`。

| 试次 | 文件大小 | 分片数 | 并发上传 | 耗时 | 吞吐量 |
|---|---:|---:|---:|---:|---:|
| 1 | 16 MiB | 4 | 1 | 239.60 ms | 66.78 MiB/s |
| 2 | 16 MiB | 4 | 1 | 188.49 ms | 84.89 MiB/s |
| 3 | 16 MiB | 4 | 1 | 211.13 ms | 75.78 MiB/s |

脚本为每次试验生成内容唯一的合成 CSV。计时从发送创建会话请求开始，到收到并解析合并完成响应结束。计时包含分片传输、服务端落盘、合并、格式与摘要校验及 MySQL 登记。生成文件、客户端计算摘要、账号认证和事后下载校验各自在计时范围之外。三次下载的 SHA-256 均与输入一致。

端到端浏览器验收后，开始基准测试前的 Java 进程峰值工作集为 324,661,248 字节（约 309.6 MiB），三次试验结束时记录到的进程生命周期峰值仍为该值。该值包含 JVM 启动和浏览器验收期间的驻留内存峰值。吞吐结果适用范围为本机单并发，不代表跨网或并发负载。

应用启动后，在仓库根目录执行：

```powershell
node .\scripts\benchmark.mjs
```

默认连接 `http://127.0.0.1:8082`，端口变化时用 `FILEVAULT_BENCH_URL` 指定本机地址。脚本输出每次的真实测量值，并在开发数据库中保留一个随机测试账号和三个合成文件。Windows 上可通过 Java 进程的 `PeakWorkingSet64` 属性另行观察进程峰值工作集。

## F7 文件规模与小并发实测

2026-11-19 在 Windows 11（构建 26300，14 个逻辑处理器）运行 Java 21、原生 MySQL 8.4、Node.js 24。服务和客户端同机回环。后端 JAR 使用 `-Xms64m -Xmx256m`，本次测量关闭定时扫描和临时分片清理。每组一次，双并发使用两个不同账号。文件为合成 CSV，各试次都有不同内容并通过完整下载 SHA-256 比对。

| 组 | 文件（MiB） | 分片 | 上传耗时（ms） | 下载与客户端摘要（ms） | 单项上传吞吐（MiB/s） |
|---|---:|---:|---:|---:|---:|
| 单并发 | 1 | 1 | 163.33 | 20.58 | 6.12 |
| 单并发 | 16 | 4 | 258.51 | 64.77 | 61.89 |
| 单并发 | 100 | 25 | 1213.89 | 217.65 | 82.38 |
| 单并发 | 190 | 48 | 2090.66 | 351.77 | 90.88 |
| 双并发 A | 16 | 4 | 270.32 | 34.16 | 59.19 |
| 双并发 B | 16 | 4 | 251.75 | 65.10 | 63.55 |

双并发组从最早发送创建会话到最晚解析完成响应为 270.32 ms。六次传输均成功，客户端错误数为 0。进程峰值工作集从启动后的 297,684,992 字节增加至测量结束时 306,827,264 字节，这是进程生命周期高水位。上传时间包含会话创建、顺序 PUT、合并和登记，不含文件生成、客户端预计算摘要及事后下载。下载时间含完整客户端下载及摘要。

```powershell
node .\scripts\benchmark-f7.mjs
```

脚本使用随机生成的开发账号及合成文件。不要在包含真实用户数据的部署上执行。此结果未测 CPU 时序、远程网络、并发上限、P95 或优化比例。
