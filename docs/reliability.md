# 上传可靠性与存储对账

## 状态和恢复

- `OPEN` 的 `received` 只包含通过磁盘长度及 SHA-256 校验的索引。数据库未见过的索引在两份列表中都没有记录。已登记但缺失或损坏的索引出现在 `repair`。用原始分片补传可恢复，其他内容返回 `CHUNK_CONFLICT`。
- 完成时合并过程重新校验分片与整文件。一致的分片无法满足声明摘要，或合并内容不符合允许的文件格式时，会话进入 `FAILED`。界面可显式重新开始，尝试中止原开放会话，再创建新会话。关闭会话的分片进入清理队列。
- 完成前取得不可变的分片元数据，按顺序一次打开一个文件，并在事务外合并。最后取得会话行锁、复核状态，随后在用户行锁下去重与登记。竞争请求可能各自执行合并，最终以其中一次登记为准。一个旧会话返回相同的文件 ID，重新创建的会话独立处理。
- 单片请求体及小文件内容在事务外暂存。短写事务仍包含文件移动、必要时一次不超过 4 MiB 的重传校验，以及去重对象存在性检查。若中止先提交，后到的分片登记会拒绝。操作正确性依赖于应用对私有目录的独占写入权限。

## 异常状态

| 中断位置 | 可能看到的状态 |
|---|---|
| 暂存期间或合并完成后、移动前 | 暂存目录留下旧临时文件 |
| 移动后、数据库提交前 | 磁盘存在、数据库无记录，确认回滚时会尝试删除本次新文件 |
| 数据库提交结果未知或补偿删除失败 | 物理文件可能需要对账确认；已提交的记录必须保留 |
| 外部磁盘丢失或备份恢复不同步 | 数据库有记录但物理文件缺失，开放会话的分片可重传 |
| 已关闭会话分片删除失败 | 记录延后重试，其他符合条件的分片仍可清理 |

## 只读扫描

从项目根目录执行。为减少扫描期间的变化，建议先停止 FileVault，维持 MySQL 运行。

```powershell
.\scripts\start-backend.ps1 -Reconcile
```

扫描复用 `.env.local` 的数据库和存储配置。工具不启动 HTTP、Flyway 或定时任务，数据库只执行 SELECT，存储目录必须已经存在。输出只有无引用对象、无引用分片、缺失对象、缺失开放会话分片、超龄暂存候选的计数。关闭会话的缺片可能是正常清理的一部分，不计入缺失开放分片。默认只把年龄超过 900 秒的磁盘文件计作无引用候选，延迟过长或并发变化仍可能影响结果。超龄暂存项也可能来自仍在运行的操作。工具保留所有扫描结果涉及的行和文件。

## 可调资源限制

| 进程环境变量 | 默认值 | 范围 |
|---|---:|---|
| `FILEVAULT_MAX_UPLOAD_BYTES` | 200 MiB | 单次文件声明，最大 512 MiB |
| `FILEVAULT_USER_OBJECT_QUOTA_BYTES` | 512 MiB | 每用户已登记的物理对象，软删继续计入 |
| `FILEVAULT_MAX_OPEN_UPLOADS` | 4 | 每用户同时开放且未过期的会话 |
| `FILEVAULT_USER_UPLOAD_RESERVATION_BYTES` | 800 MiB | 每用户开放会话声明大小，加尚未清理的关闭或已过期会话分片 |
| `FILEVAULT_STORAGE_STAGING_BYTES` | 1 GiB | 单应用进程并行暂存和合并的保守预留 |
| `FILEVAULT_STORAGE_MIN_FREE_BYTES` | 256 MiB | 暂存前检查剩余空间。外部程序仍可能抢占空间 |
| `FILEVAULT_CLEANUP_RETRY_SECONDS` | 300 | 分片清理失败后的重试间隔 |
| `FILEVAULT_RECONCILE_GRACE_SECONDS` | 900 | 无引用磁盘文件与暂存候选的扫描宽限期 |

当前扫描处理物理对象存在性，不重新计算所有历史对象摘要。暂存预留按单进程计算，多进程共享存储需要额外协调。计数大时应在维护窗口扫描。
